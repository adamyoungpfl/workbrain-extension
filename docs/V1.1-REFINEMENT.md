# V1.1 — flow & feel refinement

Not part of `docs/RELEASE-1.md` — that backlog is closed except R1-13 (store submission, gated on
non-code assets). This is a second batch: Adam's notes after actually using V1 Beta. Same "done means
accept criteria pass and `npm run check` is green" discipline as Release 1.

See `docs/V1.1-COPY-DRAFT.md` for the actual copy this batch depends on — write/approve that first.

## VB-01 · Welcome
`Home.tsx`'s `nextMove.kind === 'start'` branch, redesigned — logo lockup (adapted, not literally
ported — see below), a real "begin" moment. No new surface, no new persisted state.

**Logo**: a static (non-animated) redraw of `../modelcitizen/public/mark.svg`'s icosahedron pose, as
an inline SVG. Its gradient colors become new tokens in `design/tokens.json` under `color.brand.*`
— real, deliberate brand-color exceptions, not literals, so `npm run audit`'s "no hex outside
tokens.css" rule stays meaningful. "Workbrain" wordmark is real text (not CSS-in-JS), a new modest
type-scale entry (not `type.display`, which is explicitly site-only), colored with the existing
`--violet` token rather than importing a second, off-brand violet.

**Accept**: the welcome state renders the lockup + a real CTA using the copy in
`V1.1-COPY-DRAFT.md`; no continuous animation (one-time entrance only, skipped under
`prefers-reduced-motion`); `npm run audit` passes with zero new hex literals outside `tokens.css`.

## VB-02 · Breadcrumb → module title + progress bar
Replaces `S.questionOf(...)` in `StepView` (`Flow.tsx`). New `src/panel/components/FlowProgress.tsx`
— module title + a slim, muted, numberless bar, computed from the already-existing
`topLevelIndex(modules, pos)` / `total`. Not the `Meter` component (that's Home's separate 4-gate
macro progress). No per-module color coding — the palette's colors are semantically load-bearing
elsewhere; "thematic" here means the module's own title, not a new color or icon per module.

**Accept**: no raw numbers rendered; the bar still exposes `aria-valuenow`/`aria-valuetext` for
assistive tech even though nothing is printed on screen; axe clean.

## VB-03 · Deeper-dive disclosure
New optional `Step.deepDive?: { q: string; a: string }[]`. Small chip-style trigger under the
question; tapping reveals `a` inline. Only for questions where a real "explain this more" need
exists — see `V1.1-COPY-DRAFT.md` for which ones and why the rest keep their existing short `hint`
unchanged. `hint` is not deleted; it stays for short directive notes ("Skip if there's only one name
for it.") that aren't "deeper dive" material.

**Accept:** every `deepDive` entry's `a` is reachable via keyboard, closes on re-click, and doesn't
shift focus away from the question; `npm run audit`'s reading-level check stays at or under grade 7
including the new copy.

## VB-04 · Rephrase icon
New inline SVG (stroke-based, `currentColor`, matching `Home.tsx`'s `PERSON_ICON` convention): a
question mark whose dot curls into a partial recycle-arrow. Moves the rephrase trigger from its
current quiet text button to sit next to the question heading as a real icon-button.

**Accept:** ≥44×44 hit target; `aria-label` carries `S.rephrase`'s existing text, not a bare glyph;
axe clean.

## VB-05 · Module transition screens
New `Position` kind in `core/flow/runner.ts`: `{ kind: 'module-intro'; module: Module }`. Derived,
not stored — returned when about to hand back the first node of a module where no node in that
module has any answer yet. **Applies before modules 2–11, not module 1** (module 1's own
`orientation_ready`/`architecture_orientation` already do this job; a second welcome-shaped screen
right after VB-01's would be redundant). Renders via real `beats` playback (timed fade,
`__word__` → emphasis) — new shared infrastructure, since `architecture_orientation` already has
authored `beats` that nothing renders yet. Content in `V1.1-COPY-DRAFT.md`. A plain "continue" action
in `Flow.tsx` advances `viewing`/`history` — writes nothing to `wb:answers`, since there's no
question here to answer.

**Accept:** reopening the panel mid-module never replays a transition already passed (matches every
other position kind's resume behavior); `prefers-reduced-motion` gets the full beat text at once, no
fade; every module in `CONTEXT_INTERVIEW_MODULES` except the first gets exactly one transition,
verified by an e2e walk.

## VB-07 · The living file tree
A collapsible drawer, docked to the bottom of the panel, showing `contextOutline`'s ten sections as
a tree that visibly fills in as the interview progresses. Not a reference item — a **visual asset**
carrying the "I'm building a human operating system" feeling, and a second, structural read on
progress (VB-02's bar answers "how far through the questions"; this answers "what am I actually
building").

**This is a PORT, not new invention.** `../modelcitizen/src/components/WorkBrainContextInterview.tsx`
has a complete `FileTree` + `FileTreeRow` implementation (~lines 1648–1831) plus its CSS
(`src/app/globals.css` ~5788–5860). Every behavior below was already specified by Adam on
2026-08-19 and built there. Port it the same way R1-05 ported the questions — see
`docs/CONTENT-SOURCES.md`, and add rows there for this. Do not re-derive it.

What the existing implementation already does, all of it wanted:
- **Three derived states** — `outlineNodeReached` / `outlineNodeCurrent` fold over `answers` and the
  current question id, recursing into children. Pure functions; port to `core/` and unit-test.
- **The terminal aesthetic** — this is the "human operating system" feeling, already built. Each row
  types itself in character-by-character when *its own* state changes (`useTypewriterOnChange`,
  15ms/char), and the active row carries a blinking `▋` terminal cursor (2.2s, `steps(1)`, so it
  snaps rather than fades). Adam's own words in the source: *"the file tree also loads in like a
  terminal,"* and *"making the file look active in a way that feels familiar... an actual terminal
  cursor blip, not just a glow."* Critically, `useTypewriterOnChange` **does not replay on mount** —
  resuming a saved session doesn't re-animate every already-reached row, only rows that transition
  while you're watching. Preserve that.
- **Accordion, one section open at a time**, auto-syncing to whichever section is active, with a
  manual override until the active section itself changes.
- **Reached/current rows are real navigation; unreached rows are not.** Deliberate — jumping ahead
  would skip required questions the flow guarantees get asked. This is review navigation, not a
  shortcut.
- **Role records render as individual sub-items** under 2.1 Roles, matching how the generated file
  actually structures them.
- **Reached vs current is a strength difference in one color family** (reached = accent mixed toward
  white; current = full accent + weight), not "colored vs gray."

**`cursorForQuestionId` — check the assumption.** It does *not* map to a position in the file; it
maps a question id to `{moduleIndex, nodeIndex}` in the *flow*, resolving a repeatable's sub-question
up to the block's own start. It's the click-to-navigate resolver, and it's what `jumpToQuestion`
consumes. It was consciously left unported at R1-09 (`core/files/parse.ts`'s header: *"no
outline-browsing UI exists yet to use it"*) — that reason expires here. In this repo it must return
a `Position` (`core/flow/runner.ts`), not a `{moduleIndex, nodeIndex}` cursor, since this runner
derives position rather than storing one. `Flow.tsx`'s existing `initialPosition`/`viewing`
mechanism (built at R1-12 for Home's deep-link) is already exactly the seam this needs.

**What genuinely breaks in the port: the layout, and only the layout.** In the web app the tree is a
360px right-hand grid column. Its existing `max-width: 900px` breakpoint stacks the tree *below* the
question — which in a 400px side panel means it scrolls off-screen while answering, i.e. the one
thing this feature exists to prevent. The drawer is the re-authored part. Also missing there and
needed here: a scroll container (`.wbci-filetree` has no `max-height`/`overflow`) and
`scrollIntoView` on the current row — neither exists today.

**A11y note the port must fix, not inherit.** The source deliberately renders unreached rows at
sub-threshold contrast and justifies it as WCAG's disabled-control exemption. In this repo the
current row must be distinguishable by more than color and weight — the existing `▸`/`└─` glyph
column is the natural place to carry that signal (a distinct marker for reached vs current), since
`docs/GUARDRAILS.md`'s "nothing distinguished by colour alone" has no exemption written into it.

**Not a `Sheet`.** The design system's Sheet is "the only overlay in the system," scoped to "a short,
self-contained task," and it covers the panel. This is persistent, non-blocking, and always at least
partly visible — a docked drawer, not an overlay. It must never trap focus or block the question
behind it (that would make it a modal in everything but name — see `docs/GUARDRAILS.md`).

**Derived, never stored** — per-section state (`reached` / `current` / `untouched`) is computed from
`wb:answers` + the current `Position` on every render, same as every other derived thing in this
product. The drawer's own open/closed state is ephemeral session state (like `Flow`'s `history`),
not persisted.

**Accept**: every section in `contextOutline` renders from question one, dim until reached; the
current section is distinguishable by more than color alone (GUARDRAILS' a11y floor); the drawer is
keyboard-operable, never traps focus, and the question behind it stays reachable; collapsed by
default at ≤N px of panel height if it would otherwise crowd the question (real constraint — the
panel is 400px wide and the question is the primary object on screen); animation honors
`prefers-reduced-motion` by rendering the same state changes without motion.
