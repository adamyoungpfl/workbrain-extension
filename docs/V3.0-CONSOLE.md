## The plan, the flags, the calls

1. **Download expands.** The Home download row opens to a component list —
   each file with its presence state, per-file download, and "the full
   workbrain folder". FLAG: a real folder/zip download needs either a
   dependency (banned without cause) or sequential downloads. CALL: a
   minimal STORE-method zip writer in core (no compression, ~100 lines,
   tested against known bytes) — a .zip that every OS opens, no dependency.

2. **The universe becomes the app's canvas.** The splash's seven-lattice
   field replaces the wall panels behind every surface — one component,
   shared with the splash intro, identical faintness (consistency IS the
   ask). WallPanels benches like SplashStage did. FLAG: seven continuously
   turning lattices behind every screen is a standing GPU cost — measured
   before shipped; reduced motion gets the still field.

3. **Narration signal audit.** The stored pref persists today; the audit
   is that every surface RESPONDS to it. Verified per-surface, fixed where
   found wanting.

4. **The A/B filler rule.** A = speaker on: normal narration only. B =
   speaker off: pressing the mark plays the filler once, flips to A, and
   the NEXT screen reads normally with no filler. Requires finding what
   the "mitigating speech fillers" are in the current engine (the
   `drop` lead-ins) and wiring the state machine around them.

5. **The peaks take over the voice.** An animated W Peaks for the splash
   intro, and the narrator mark becomes the peaks as a VOICE VISUALIZER —
   three bars that move while reading (driven by the speech engine's word
   boundaries — Web Speech exposes no amplitude), muted = flattened, in a
   top-right cluster.

6. **Jump-to's Home button** gets save-point pop.

7. **Jump-to's questions collapse by section** — module groups, collapsed
   by default. (His "cool filter visual or just collapsing sections" —
   the sections ARE the filter; no second control invented.)

8b. **Home restructures around the queue** (the mid-round addition):
   fresh Home leads with YOUR NEXT MOVE (a preview of the next question
   to complete or refresh, oldest first, expandable), the old section
   renames to YOUR WORKBRAIN, and finishing the featured item sweeps to
   the next open/stale one the way a grammar check walks the whole doc
   from wherever you started. FLAG: the sweep is a sequencing feature in
   the runner, not a Home widget - it needs its own maintenance queue in
   core (open + stale detection) and lands as its own pass late in the
   round.

8. **The file main page wears the lower panel's treatment** — the brain
   model + list page matches the drawer's color and presentation.

### Pass 3b — the silence in dev builds (2026-09-02, found in dogfood)

Adam: "I am getting no sound on any screens, I don't see the equalizer or
any motion from the icon on the interview canvas either." The cause: dev
builds run under React StrictMode, which mounts every effect twice -
speak, cleanup-cancel, run again - and pass 3's A/B guard marked the
narration spent ON THE SPEAK PATH, so the second run skipped and every
dev screen spoke for ~0ms then went quiet. No speech, no word boundaries,
no dance. Production single-invokes, which is why every gate stayed green
while the dogfood build was mute - a class of bug the immune gate
STRUCTURALLY cannot catch, and the person's own build can.

The fix is an omission: spent means PRESENTED WHILE MUTED, the only
reading the A/B rule needs, and the speak path never marks it. A
StrictMode-wrapped unit test now pins the survival ("ends SPEAKING, not
cancelled") - the exact failure, reproduced in the suite that runs on
every gate.

### Pass 3f — the narration joins the clips (2026-09-03)

THE DIAGNOSIS, from Adam's own wbAudio.trace() paste - textbook: every
clip play->playing->done, flawless; every engine utterance tts:speak with

THE CURE: the interview's static narration ships as bundled clips.

clipKey.ts): reworded copy hashes elsewhere, so a stale clip can never
speak old words - the miss falls back to the engine and the drift test
(narrationClips.test.ts) fails the build until the render re-runs.

useNarration plays the clip first; the engine remains for interpolated
lines and missing files, alive-guarded so an abandoned screen cannot
speak over its successor. THE HARNESS SEAM is a window global
