# V1.2 — motion, the drawer, and a visual metaphor

Second round of Adam's notes, after clicking through V1.1. Same discipline as
`docs/V1.1-REFINEMENT.md`: done means the accept criteria pass and `npm run check` is green.

VB-14 is a **spike**, not a build task — it needs a direction chosen before anything is committed to.

---

## VB-09 · Dev-only reset
Resetting during dogfooding currently means opening DevTools on the panel and running
`chrome.storage.local.clear()`. That's friction on every single test pass.

Add a reset affordance that exists **only in development builds** and is stripped from production
by the bundler (`import.meta.env.DEV` under Vite, so it dead-code-eliminates — verify it's absent
from the built `dist/` bundle, don't assume). A keyboard chord in the panel is enough; it needs no
visible chrome.

This is **not** a settings page (`docs/GUARDRAILS.md` rules those out) because it never reaches a
real user. Clear both `chrome.storage.local` and `chrome.storage.sync`, then re-render to the
welcome state without needing a manual reopen.

**Accept**: works in `npm run dev`; a `grep` of the production bundle finds no trace of it; the
audit still passes.

## VB-10 · Questions type themselves in
Old-school keyboard feel: each question types in quickly on arrival. Same for the module label in
the status bar — but only when it actually changes, not on every question within the same module.

**Most of this already exists.** VB-07 ported `useTypewriterOnChange` for the file tree, and the
sibling repo has a plain `useTypewriter` variant that animates on mount. Read both before writing
anything. The distinction matters and is already solved there:
- **Question text** wants the mount-triggered variant — every new question types.
- **Module label** wants the change-triggered variant — types only when the module changes.

**Two real risks to design against, not discover later:**
1. **This is a 49-question interview.** Even 400ms of typing per question is 20 seconds of pure
   waiting across a pass, and it lands on every single screen. Type fast (~8–12ms/char) and make it
   **skippable** — any key or click completes it instantly. Old-school feel without the tax.
2. **Never delay input.** The field, pills, and Next must be usable while the text is still typing.
   A person who knows the question already should never be gated behind an animation.

**Reduced motion**: full text immediately, no typing. Not a shortened animation — none.

**Accept**: a question is fully readable and answerable before its animation finishes; a keypress
completes the text instantly; the label doesn't re-type when moving between questions inside one
module; reduced motion shows everything at once.

## VB-11 · Dock the navigation to the drawer
Back / Next / Skip currently sit in the flow's own footer, with the drawer below them. Peg them to
the top edge of the drawer instead, so the controls and the drawer read as one docked unit and the
buttons stay put as the drawer resizes.

**Accept**: the nav stays visually attached to the drawer's top edge at every drawer height; it
never overlaps the question; keyboard order still reaches the question's own controls before the
nav; the 44px floor holds.

## VB-12 · A draggable drawer with a real grab handle
Today it's collapsed-peek / expanded. Make it **draggable** — the person drags it up or down to
expose as much file structure as they want, anywhere between a minimum peek and a maximum height.

Replace the "YOUR FILE SO FAR" label with a **proper section divider that looks grabbable** — the
software-panel convention (a divider rule with a centred grip). It should be obvious it's a handle
without a tooltip explaining it.

**Requirements:**
- Pointer drag, and **keyboard equivalent** (arrow keys on a focused handle with
  `role="separator"` + `aria-valuenow`) — a drag-only control fails the keyboard-path guardrail.
- Height is **ephemeral session state**, never persisted (`docs/ARCHITECTURE.md`, nothing derived
  or incidental is stored).
- A minimum height that always leaves the question readable; a maximum that never fully covers it.
- Honour `prefers-reduced-motion` on the snap/settle, not on the drag itself.

**Accept**: draggable by pointer and by keyboard; the question is never fully occluded; height
resets on reopen; axe-clean; the handle reads as a handle to someone who has never seen it.

## VB-13 · The animated mark
Adam's call, overriding VB-01's static decision: use the **animated spinning mark** from the Model
Citizen site on the welcome screen, and add a small spinning mark to the **left of the status-bar
label**.

Source: `../modelcitizen/src/components/ModelSphere.tsx` — a `requestAnimationFrame` loop
recomputing real 3D icosahedron geometry per frame. `BrandMark.tsx` in this repo is the static
single-pose transcription of it, already built and already tokenized; extend that rather than
re-transcribing the geometry.

**Two things to get right:**
1. **`prefers-reduced-motion` must stop the rotation entirely** — falling back to exactly today's
   static mark, which already exists and already looks finished. This is the cheapest possible
   still equivalent, since it's the component we already ship.
2. **A permanently-spinning mark in the status bar is on screen for the entire interview.**
   Continuous peripheral motion next to text someone is trying to think about is a real
   concentration cost, and it's the one place in this product with unending animation. Worth
   trying **spin-on-change** (it turns when the module changes, then settles) before committing to
   continuous — same brand moment, no permanent motion. Build continuous as asked; show both.

**Accept**: rotates on the welcome screen; a reduced-motion user gets the static mark and no rAF
loop runs at all (assert the loop isn't merely invisible); the status-bar mark never shifts the
label's baseline as it turns; no measurable frame cost on the interview screens.

## VB-14 · SPIKE — a visual metaphor for the file
**Not a build task.** Adam: *"iterate on the visual concept to do something more visually engaging
that illustrates the file structure without having to be true to it… like the Health Pane where you
can see the brain that has been created and explore it… a visual metaphor that works."*

The brief in one line: **make the drawer show the thing they're building, not the table of contents
of the thing they're building.** Explicit permission to abandon literal fidelity to the ten-section
outline.

Constraints any direction has to survive:
- 400px wide, and sharing vertical space with the question.
- Must still answer "how far am I" and "what's left" — it replaces a progress indicator.
- Sections must stay **navigable** — VB-07 built real click-to-navigate and it shouldn't be lost.
- Derived from `wb:answers` on every render; nothing new stored.
- Needs a reduced-motion form that still conveys structure and progress.
- Must not become a second thing to learn. If it needs a legend, it has failed.

Directions spiked (see the artifact linked from this task): the brand mark as a growing knowledge
graph, a constellation, and a layered system stack. **The graph direction is the one worth
noting**: Workbrain's own logo is already a node-and-edge network, so the thing they assemble by
finishing the interview is literally the brand mark. The metaphor is already sitting in the
product's identity, unused.

**Exit criteria for the spike**: one direction chosen, or all rejected with a reason. No code
lands until then.
