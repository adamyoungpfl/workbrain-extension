Written 2026-08-25, from `docs/SPIKE-skills-actions.md` and `docs/OPEN.md`.
**#1 and #5 were RESOLVED by Adam the same day — see #1 below. The resolution is stronger than
either option this page originally offered, and it retires #5 entirely.** #2–#4 and #6 still gate

## 1 · RESOLVED (2026-08-25) — there is no Actions interview

Adam: *"whether the actions flow actually provides any additional value to the overall file, or if
simply enhancing skills to reference the files and tools being used in the skill and then making
the actions.md file build a paid service offering… we just make every skill capable of telling us
what is needed to connect and permission the skills for that user… every skills file is a possible
actions file service waiting to happen."*

**The decision: the Actions interview is cancelled. Actions.md becomes a file DERIVED from
Skills.md**, and the flow is two interviews — Context, then Skills — with the third file generated.

### Why this is the right answer, checked against the repo

- **The value question answers itself once you name the audience.** Context tells a chat assistant
  who you are; Skills tells it how to do your work — both are consumed by the AI the person hands
  them to. Actions.md's content ("this should run automatically, it needs read access to the
  tracker") was never for the chat assistant. **Its audience was always the implementer** — the
  person later, or TIM. A file whose reader is the implementer doesn't need an interview; it needs
  an accurate derivation plus the connection requirements.
- **The cannibalisation fear dissolves structurally** instead of being managed by a depth line:
  there is no self-serve Actions interview to cannibalise. And the derived file is the TIM
  engagement's perfect input — a statement-of-work generator wearing a text file.
- **The data model already agrees.** `SkillDraft = {name, trigger, inputs[], tools[], steps[],
  output}` — inputs and tools are ALREADY fields (confirmed in `workbrain/shared.tsx`). The
  sibling's whole Actions builder was: which skill → what may it do / what needs your OK → your
  actions.md. Steps one and two collapse into per-skill questions; step three is generation.
- **The service ladder already expected this.** The gate-mapped tiers (Coaching → AI Enablement →
  TIM) put "Act" where the paid ladder starts; the Actions builder's own header said the deep
  version *"is the paid 1:1/Team work."*
- **"Nothing derived is stored" fits perfectly.** Actions.md becomes a pure fold over Skills
  answers, regenerated at view and download exactly like Context.md's preview. Zero new storage,
  zero staleness — edit a skill and the actions file is already current. The Skills→Actions lock
  ordering the spike worried about becomes automatic: the derivation IS the dependency.
- **Nothing user-facing has to be walked back.** `fileActionsWhat` is 'What should happen
  automatically' — still exactly true. CLAUDE.md's three-file description — still true. The third
  slot survives; only what unlocks it changes.

### What moves INTO Skills (the whole cost, and it is small)

Two light per-skill additions, not an interview smuggled in:

1. **Sharpen the tools/inputs capture** the fields already have, enough to derive connection needs:
   which system, and where the data lives — with "not sure" as a first-class answer.
2. **One chips question: "Would you want this to run without you?"** — I'd run it myself / draft it
   for my approval / fully automatic / never. This is the approval-gate PATTERN, the one thing the
   sibling builder said was genuinely the same for everyone.

**Guard: if the Skills interview grows by more than ~2 questions per skill, the Actions interview
is re-entering through the back door.** That is the failure mode to watch in review.

### What the generated Actions.md contains

- The sibling's framing paragraph, **verbatim** (it exists; port it byte-for-byte).
- Per skill: what it touches, the access it would need, the person's run-preference in their own
  chips answer, and what is still unknown — *"not sure where this lives"* becomes a printed
  finding: the shortlist of questions to ask IT, which is genuinely useful to someone who never
  buys anything.
- A **ways-to-connect section**: links to Adam's DIY enablement content (sibling-site work, feeds
  the engagement loop) — so the file never dead-ends into "hire us."
- The **fixed safety footer, verbatim**.

### The two traps

1. **The slot must not become a paywall wearing a diagnosis** (this page's own earlier warning, now
   pointed at the right target). The third slot unlocks into a REAL generated artifact the person
   keeps — with the DIY paths inside it — and the service door is the existing quiet "talk to a
   person" pattern beside it, never the unlock itself.
2. **Skills bloat** — see the guard above.

### Presentation (recommended, cheap to change)

The third slot stays on Home with its current name and description. Locked until Skills has at
least one connectable skill; then it reads as **generated** — openable, downloadable, never
interviewed. The lock note's language shifts from "Finish Skills.md first" to the same fact said
of a derivation.

## 2 · Where does the "what repeats?" question live? — gates Skills

The product already promises this. `WorkBrainContextBuilder.tsx` tells people *"This list becomes
the skills you build at Gate 2 — you won't have to invent them later."* **That promise is not kept
by anything that ships:** the ported Interview has no recurring-deliverables question, and
`responsibilities_list` is free text, which cannot seed a repeatable the way `role_names` seeds
`roles`.

- **(a) Add one `multi` question to Context.** Delivers the promise. Breaks the verbatim-port
  contract and ripples into `CONTEXT_FILE_OUTLINE`, `SECTION_HALF_LIFE_DAYS`, the round-trip
  fixtures and every full-flow test.
- **(b) Ask it as Skills' own opening question.** Self-contained, no ripple, loses the "you won't
  have to invent them later" payoff.

**Recommendation: (b)** — and for a stronger reason than the spike gave. Context is already 49
screens and about fifteen minutes. **(a) taxes the file everyone builds first in order to benefit
the file only some people build second.** That is the wrong trade regardless of how cheap the
adapter makes it.

*(V2.0's FLAG 2 means flow changes go through the adapter rather than `source.ts`, so (a) is
cheaper than it looks. It still ripples, and the tax on Context is the real objection.)*

## 3 · What does "finished" mean for a file whose length the person chooses? — gates Skills

Skills is **repeatable-dominated**. One skill? One per named deliverable? Never finished?

`summariseSectionHealth` has no answer today, and `fileFinished` feeds `slots.ts`, Home's locked
rows, the file toggle, the breadcrumb, `nextMove` and the globe — the same completeness-rippling
trap V2.0's VB-61/63 already hit once.

**Recommendation: one skill finishes the file, and the file never stops being addable-to.**

Two reasons. **Mechanically**, if "finished" needs N skills then every downstream surface stalls
behind a number nobody agreed to, and Skills would gate Actions on that number. **In principle**,
it is the product's own position — *"the biggest risk to failure is failure to launch."* A file with
one real skill in it is worth handing to an AI. A file with nine and a locked badge is not worth
more.

## 4 · Does Skills v1 have a team module at all? — gates Skills' shape

`docs/OPEN.md` #3 (*how much of a pack may a person edit before it stops being the team's method*)
decides whether pack skills are **copied into `Skills.md` or referenced read-only**, and that
decides whether Skills has a team module.

**Recommendation: ship Skills v1 with no team module, and leave #3 open.** Packs are not built.
A module about editing packs, in a file that cannot receive one, is a module about nothing. The
`personal/team` marking on each skill still goes in — §07 splits ownership and that marking is what
makes the split possible later — but the module that would explain it waits for packs.

This one is cheap to reverse and it takes a genuinely unresolved question off the critical path.

## 5 · RETIRED with #1 — there is no interview to write an ending for

`docs/OPEN.md` #5 asked what the Actions interview says to someone who answers "not sure" twice.
There is no Actions interview. The thing the question was protecting survives in the derivation:
**"not sure" is a first-class answer on the skill, and the generated file prints it as a finding**
— the shortlist of things to find out, useful to someone who never buys anything. Open since before
Release 1; closed by removing the surface it was about.

## 6 · Name · Repeat · Act · Share, or Remember … Spread?

The extension says **Name · Repeat · Act · Share**. The sibling repo says **"Remember"** for gate 1
in three of four sources and **"Spread"** for gate 5. Nobody has reconciled them.

It does not block the build, but it blocks the copy in both new files, and renaming user-facing
words after they ship is the expensive way to do it.

**Recommendation: the extension's four win.** `CLAUDE.md`'s copy rules say buttons are verbs the
person would say — and the distinction is exactly right: **"Remember" is what the product does;
"Name" is what the person does.** Every other word in this interface is written from the person's
side. Then fix the sibling repo to match, rather than the other way round.

| Answer these | And this becomes buildable |

| #2, #3, #4, #6 | **Skills** — 6 modules, ~18–20 questions (the two per-skill additions from #1 included), converted from a 1,803-line production wizard |

**No new question `kind` is required for either** — that is the spike's best finding and it should
be defended, because `QuestionKind` is consumed by `Flow.tsx`, `generate.ts`, `parse.ts`,
`nodeDetails.ts`, `nodeSummary.ts` and `ideas.ts`.

Everything else comes free from `Module[]` + an `Answers`: the runner, `findPosition`, reflect,
deep-dive, module transitions, the ideas button, `FileTree`, `sectionHealth`, `Beats`, cues,
`addAnother`, and the work brain.

### Two things to carry into the build whatever gets decided

**Prefix the ids from question one — `skl*`, `act*`.** `SECTION_HALF_LIFE_DAYS`, `DEEP_DIVE`,
`ADD_ANOTHER` and `moduleIntros` are flat `string → value` maps keyed on `sec1`…`sec10`. A Skills
outline that reuses `sec1` silently inherits Context's 365-day freshness clock. No error, no test
failure, wrong answer.

**`skillLibrary.ts` is shape, never words.** The spike called it a validated answer-space; it is 53
entries of placeholder content the file itself flags as unreviewed. Corrected in
`docs/CONTENT-SOURCES.md`, repeated here because it would read fine in review and survive.
