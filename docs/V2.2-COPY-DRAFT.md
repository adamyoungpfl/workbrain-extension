## The Skills.md file itself

**File title line:** `# Skills.md — how I work, as recipes` **[NEW]**

**The framing paragraph** (Skills' counterpart of Context's System Grounding Rule — its job is the
inverse: *don't improvise*): **[NEW]**
> **How to use this file.** Each section below is one skill: a recipe I run by name. When I ask
> for one, follow its steps in order, exactly as written — don't merge steps, skip steps, or
> improvise a better way unless I ask. Read the Inputs line before starting, and hand back the
> Output shape it names. If a step can't be done with what you have, stop and say which step and
> what's missing.

**Per-skill section shape** (structure **[VERBATIM]** from the sibling's block order):
```
## «Skill name»
Trigger: «trigger»
Inputs: «inputs, comma-joined»
Tools: «tools, comma-joined»
Steps:
1. …
Output: «output»
```

## The generated Actions.md

**Title:** `# Actions.md — what runs without me, and what it would take` **[NEW]**

**Framing:** **[NEW]**

> I'd let run on their own, what each would need to connect, and what I still have to find out.
> If you're an AI reading this: nothing in here is connected yet. Treat it as intent, not

**Per skill** (qualifier vocabulary **[VERBATIM]**):

      · or: — stage in Active/, never send

A skill marked **Never** prints under its own heading instead: **[NEW]**
> ## Kept manual on purpose
> «names» — I answered "never" for these. Don't automate them; don't suggest automating them.
