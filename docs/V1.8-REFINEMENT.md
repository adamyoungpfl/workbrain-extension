## VB-42 · Follow-up questions, one at a time, rotating
Replace the current row of deep-dive chips. Instead: **one follow-up question at a time**, as a
**text link** (blue, or a dark aqua green — or alternating), **rotating every 5 seconds**, appearing
in the same style as the question itself. The list keeps renewing until the person clicks Next or
starts typing an answer. The revealed definition gets that same text display area.

**This reworks VB-16, which shipped 2026-08-23** — the shimmer-once attract and expand-in-place,
where siblings animate out and the chosen bubble becomes its answer. That work is four days old.
Decide whether the rotation *replaces* expand-in-place or wraps it: if a rotating link still expands
in place when clicked, most of VB-16 survives and only the presentation changes. If it does not,
`core/motion/disclosure.ts` and its FLIP machinery become dead code and should be removed
deliberately, not orphaned.

**The accessibility problem, and it is a real one, not a nitpick.** WCAG 2.2.2 (Pause, Stop, Hide)
applies to any content that **auto-updates, starts automatically, lasts more than five seconds, and
is presented alongside other content** — which describes this exactly. A five-second rotation next
to a question someone is trying to answer needs a way to pause or stop it, and it must not steal
focus or move a link out from under a pointer mid-reach. Also: rotation must stop the moment they
start typing (Adam already said this) *and* on hover/focus, or a link can change identity between
the decision to click and the click.

`prefers-reduced-motion` should show the follow-ups without rotation at all — most likely the
current list, which is what it is for.

**Accept**: one at a time, rotating on a 5s cycle; stops on typing, hover, focus and on Next; a
visible way to stop it; never steals focus; reduced motion shows a static list; contrast holds for
whichever link colour is chosen (aqua-green on white is the risky one — measure it).

## VB-43 · An illustration style for the question area
Make the follow-up area more visually interesting — **a consistent art style** giving a familiar
image that makes perceived-complicated terms easier to digest through context clues.

**This is the largest unscoped item in the batch.** Concretely undecided: what the art *is*
(spot illustration? icon per concept? one recurring character or motif?), how many pieces are
needed (one per deep-dive? per module? per question?), who draws them, and how they ship (inline
SVG keeps the no-network guarantee; anything raster inflates the bundle).

There are 26 questions carrying deep-dives today. An illustration each is a real commission. **Pick
the smallest version that tests the idea** — one motif on the three or four questions people
actually stall on — before committing to a set.

Constraint: whatever the style is, it must survive `prefers-reduced-motion`, must not rely on
colour alone to carry meaning, and must be inline (no CDN, no remote asset — `docs/GUARDRAILS.md`).

## VB-45 · List rows carry the brain's orbs
The icons left of each section label in List become **the coloured orbs from the Brain visual**, so
an orb stays the same object across both views and the morph reads as one thing moving rather than
two things swapping.

This is the natural completion of **VB-32** (the orb flies to the row's own glyph). Today that glyph
is the ASCII `[x]` / `[>]` / `[ ]` tile — VB-33 deliberately kept it because state must survive
greyscale. **So the orb must carry state without colour too**: shape, fill, or a mark. Do not lose
the greyscale guarantee to gain the colour match — extend VB-19's greyscale assertion to whatever
replaces the tile.

## VB-46 · Count, percentage and status, bundled right
Per row, bundle **X of Y**, **%**, and the status pairing at the **right end** of the row.

- A row at **0 of X** is **greyed out**, showing **0%**.
- A row that is **active in the flow**, or has **at least one of X complete**, is **illuminated**.
- The row **actively being worked on** gets a **pulse or glow**, marking it as the live area.
- **The same rule drives the Brain visual**, so both views agree about what is live.

Most of this exists — VB-33 already renders count, percentage and state per row, and
`core/flow/sectionHealth` derives all of it. The changes are the right-end bundling, the greyed
0-state, and the pulse on the active row.

**Put the live-row rule in `core/`** as one pure function both views read, rather than implementing
"which row is live" twice. That is the whole point of "the same flow dictates the brain visual".

The pulse is perpetual motion on the active row for as long as someone is on that section —
`prefers-reduced-motion` must render the live state without it (a static ring or fill), and it
should be quiet enough not to compete with the question above.

## VB-47 · A file-type toggle where the "not yet" tag was
Remove the `[ ] 9 not yet` summary tag. That area above the list becomes a **toggle between the
file types** — currently Context, Skills, Actions.

**This overlaps V1.7's VB-36, which is being built right now** — Home is becoming a shelf of file
slots with Skills and Actions shown locked. That gives two places to switch files. Decide which is
canonical: Home as the shelf and the drawer toggle as a shortcut within a file, or the drawer toggle
as the real switcher and Home as a landing page. Shipping both without deciding gives the product
two competing navigations for the same thing.

Locked files must behave consistently in both: a toggle to Actions when Actions does not exist has
to say what unlocks it, exactly as `FileRow`'s locked variant does.

## VB-48 · The brain pulls back — a work brain above the context brain
**The concept item.** The Brain visual gains a zoom level *above* the current one: the Context brain
becomes a **child** of the **work brain**, which carries each file as its own node. Both Brain and
List then navigate the whole work-brain surface consistently.

This is a genuinely good idea and it is also the biggest thing in the batch. What it requires:
- **A second zoom tier.** `BrainGlobe` already has orbit → fly-into-a-section → sub-node split.
  This adds a level above orbit. Confirm the existing camera and `zoomT` machinery generalises to
  three tiers rather than assuming it does.
- **A node per file at the top tier** — Context, Skills, Actions — each expanding into that file's
  own solid. Only Context has content today, so Skills and Actions render as locked/empty nodes,
  matching VB-47 and VB-36.
- **Shared navigation state** with List, so switching file or zoom level in one view is reflected
  in the other.

**This makes the `wb:answers` namespacing decision blocking.** It was flagged as cheap-now in V1.7:
`wb:answers` is one flat store, and three interviews sharing it need namespacing by flow or separate
keys. A work brain that shows three files as peers cannot be built honestly on a store that only
represents one. **Settle that before VB-48, not during.**

## Conflicts and decisions to settle first

1. **VB-42 vs VB-16 (shipped four days ago).** Does the rotating link still expand in place when
   clicked — keeping most of VB-16 — or does rotation replace disclosure entirely, making
   `core/motion/disclosure.ts` dead code?
2. **VB-47 vs V1.7's VB-36.** Two file switchers. Which is canonical — Home as the shelf, or the
   drawer toggle?
3. **`wb:answers` namespacing.** Deferred once already. VB-48 cannot be built without it.
4. **How much perpetual motion is acceptable.** V1.8 adds a 5-second rotation on every question
   (VB-42) and a pulse on the active row (VB-46). The status-bar mark was deliberately changed from
   continuous to once-per-module on exactly this reasoning, and the deep-dive shimmer ships as a
   one-time attract for the same reason. These two would reverse that trend on the busiest screen
   in the product. Worth a deliberate call rather than arriving there feature by feature.
