## The shape (supersedes the spike's 6-module guess)

The spike guessed 6 modules / ~18 questions by mirroring the wizard's steps as modules. Decision #3
(one skill finishes the file; repeatable-dominated) makes the natural shape smaller: **3 modules,
with the wizard's whole step ladder living as fields inside one repeatable block** — exactly how
`roles` already works in Context.

| Module | Holds |
|---|---|
| `skl1` · What repeats | Intro beat + the seed `multi` (decision #2: the "what repeats?" question opens Skills — the promise Context's Builder made, kept here) |
| `skl2` · The recipes | The `skills` repeatable, seeded from skl1's multi — one record per deliverable, ~9 fields (below) |
| `skl3` · Worth handing over | The wrap: what the file does now, the proof CTA, and the line that Actions.md just built itself |

**The repeatable's fields, in order** (wizard step → field, with the two Actions absorptions):

1. `skill_name` — seeded from the multi pick (the `ROLE_NAME_SEED_FIELD` pattern).
2. `skill_trigger` — chips, `TRIGGER_SEEDS` verbatim, "Ad Hoc" default *and defaulted for the same
   documented reason the wizard defaults it*.
3. `skill_inputs` — multi-chips, `INPUT_SEEDS` verbatim + free entry.
4. `skill_tools` — chips, `TOOL_SEEDS` verbatim + free entry. *(Actions absorption 1a — the
   sharpened "which system" capture the derivation reads.)*
5. `skill_data_home` — chips + free: where does what this reads actually live? **"I'm not sure" is
   a first-class chip**, never an error. *(Absorption 1b — the derivation prints it as a finding.)*
6. `skill_steps` — open text with `interpret: ai-assist`; `buildPrompt` is the wizard's
   `stepsAssistPrompt` adapted (it already grounds on name/trigger/inputs/tools and asks the AI to
   interview first — the VB-78 shape, shipped in the sibling for a month).
7. `skill_output` — chips, `OUTPUT_SEEDS` verbatim + free.
8. `skill_autonomy` — chips: run it myself / draft for my approval / fully automatic / never.
   *(Absorption 2 — the approval-gate pattern.)*
9. `skill_owner` — chips: mine / my team's. *(Decision #4: the marking ships, the module doesn't.)*

That is the whole interview. **The bloat guard from decision #1 holds: absorptions are fields 5 and
8 — two, exactly.**

## Tasks

### VB-80 · Lift the per-file constants into a `FileCopy` record
`generate.ts`/`parse.ts` already take `modules`/`outline` as parameters; what doesn't generalise is
four module constants (`FILE_TITLE`, `fileIntroLine`, `GROUNDING_RULE_HEADING`,
`SYSTEM_GROUNDING_RULE`) and `parse.ts:258`'s hardcoded `'System Grounding Rule'` validity check.
Thread a `FileCopy` through instead. Mechanical, copy-free, and it is the prerequisite for
everything else — **build first, before sign-off if convenient.**

### VB-81 · `skillsSource.ts` + `skillsAdapter.ts`
The interview above, ids `skl*` **from question one** (the spike's silent-collision risk: the
half-life, deep-dive, add-another and module-intro maps are flat string maps — a Skills `sec1`
would inherit Context's 365-day clock with no error). Seeds ported byte-for-byte; adapted copy
marked in the draft. Add a unit test that asserts *no Skills id appears in any Context-keyed map*.

### VB-82 · The `skills` repeatable
`reconcileSeededRepeatable` + `applySeededAddAnother` + `seededNameTaken` all exist (the V1.4
lesson is already learned — an added record not in the seed answer must survive). `addAnother`
entry: "another skill?" mirroring VB-20's roles loop. Half-life for `skl*` sections: propose 180
days (skills drift faster than identity; the number is Adam's to veto in the copy review).

### VB-83 · Skills.md generation
One file, one `## <skill name>` section per record, each section the sibling's own block order
(Trigger / Inputs / Tools / Steps / Output — the `skill.md` structure, folded into sections of a
single Skills.md). The **framing paragraph is new copy** (in the draft): its job is the inverse of
Context's grounding rule — *follow the recipe exactly, don't improvise*. Same
generate-parts-equals-download construction as Context; round-trip test against `parse.ts` with the
`FileCopy` from VB-80.

### VB-84 · The Actions.md generator — a fold, not a flow
`deriveActionsFile(skillsAnswers): string`. Pure, in `core/files/`, regenerated at view/download —
never stored ("nothing derived is stored" applies literally). Contents per the decision doc:
- Title + framing (draft).
- Per skill: the action line in the sibling's own qualifier vocabulary — autonomy chips map to
  `requires my approval` / `stage in Active/, never send` / a "runs itself" line for `fully
  automatic` / **omitted entirely for `never`** (a skill the person said never to automate does
  not appear as an action; it appears in the "kept manual on purpose" line).
- The connection requirements: tools + data-home per skill, with `not sure` printed as the
  **findings list** — the questions to ask IT.
- The ways-to-connect section: links to Adam's DIY content (site work; the section ships with a
  placeholder line until the content exists — flagged, not hidden).
- The `## Default` footer **verbatim**: *"Every action above requires approval unless this file
  says otherwise. Nothing in this skill sends, closes, or modifies without me saying yes."* Never
  a field, never configurable — the sibling's comment explaining why ports with it.

### VB-85 · Home, slots, and the third slot's new meaning
`slots.ts`: Skills joins `BUILT` (unlocks when Context is finished, as the lock copy already
promises). Actions.md's slot becomes **generated**: locked until `fileFinished(skills)` — which,
per decision #3, is *one finished skill* — then openable/downloadable, never interviewed. Lock-note
copy in the draft. The quiet "talk to a person" row already exists on Home; **nothing new is added
next to the slot** (trap #1: the service door is the existing pattern, not a new one).

### VB-86 · The globe and the drawer for a second file

breadcrumb file-chips, and `nextMove` read the new `fileFinished` — the completeness ripple decision
#3 was priced for.

   answer spaces only.

   in the build's e2e timing pass. If a record drags, candidates to trim are `skill_owner` (could
   default to "mine" with a quiet toggle) — decision for the copy review.
