# V2.0 — the capture flows, the home shelf, and what a file is for

Tenth round, captured 2026-08-24 after Adam's pass over V1.9. **Not started.**

**Three things here are bigger than they look**, flagged at the end: one removes an accessibility
control that exists to satisfy WCAG, several change the *ported interview data* rather than its
presentation, and one edges toward telemetry. Read the flags before scheduling.

## Trim — small and unambiguous

### VB-55 · Drop the right-hand status pill in List
Remove the `[x] Done` / `[>] Here` marker from the right end of each row.
**Check before deleting**: VB-19's greyscale guarantee says state must survive colour removal. The
LEFT orb already carries it three ways (`dim` hollow+dashed, `lit` filled+tick, `live` filled+caret
+ring), so the pill is probably redundant — but re-run the greyscale assertion after removing it
rather than assuming, and keep the count/percentage that share that column.

### VB-56 · Drop the blinking cursor
Remove the terminal cursor after the selected node. The pulse on the left icon is enough.
It came from the sibling app's terminal aesthetic (R1-08/VB-07); the panel has moved past that
register. One less piece of perpetual motion — consistent with every other call made this month.

### VB-57 · Follow-up link tidy
- **Remove the "Show all" link** — see FLAG 1, this is not a pure deletion.
- **Left-justify** the follow-up so it aligns with the question above it.
- **Remove the underline** on the link.
**Underline removal needs a replacement signal**: `docs/GUARDRAILS.md` forbids distinguishing
anything by colour alone, and an underlined link with the underline removed is a coloured word.
Weight, a chevron (already there), or a dotted rule can carry it — pick one and assert it.

### VB-58 · Centre the save note
Centre *"Saved on this device · Nothing leaves your browser"* above the nav, light padding.
VB-44 just tuned this to 8px foot / 25px above the nav's painted words, deliberately mirroring
VB-41's 29px below. Keep that arithmetic and change only the alignment, or restate both numbers.

### VB-59 · Simplify the work-brain back control
Replace the "Back to your work brain" chip with an icon or visual cue.
Keep a real accessible name on it — an icon-only control still needs one, and it still needs 44×44.

## The capture flows — real changes to how the interview collects things

### VB-60 · Choosing 1:N as orbs
The roles question (`role_names`, multi-select) stops being pills. Options become **inactive,
dimmed orbs with a glowing outline that rotates through the available choices**, indicating you can
pick one or several. **Add-new becomes a smaller, faintly glowing orb with a pulsing `+`** — an
anchor to action when nothing on screen looks clickable.

This is the brand's own object arriving in the question area, which is a good instinct. Constraints:
- The rotating outline is **auto-updating content** — same WCAG 2.2.2 question as the follow-up
  rotation, and the same answer required.
- Orbs must stay selectable by keyboard with a visible focus ring, and selection must not be carried
  by glow alone (a check, a fill, a mark).
- `PillGroup`'s existing roving-tabindex and arrow-key behaviour is a shipped accessibility
  contract — whatever replaces it must keep it.

### VB-61 · My World becomes a required, typed, repeating capture
Today `entities_gate` is a yes/no that can skip the whole block. Change to: **assume at least one**,
as a required gate for a complete file, and let the person **choose which kind of item** each one is,
since this repeats.

### VB-62 · A new item-capture cycle
For each item: **(a) type → (b) name → (c) description → (d) synonyms or shortcuts → repeat.**
Note this reorders today's flow, which asks name first (`entity_name`, `entity_type`,
`entity_relevance`, `entity_aliases`). Type-first is better for a typed repeat — it lets the later
questions phrase themselves for a person versus a tool.

### VB-63 · Initiatives: one minimum too
Same as VB-61 — at least one initiative required for a complete file. **The existing order is
right** and stays; only the gate changes, plus the add-another after each.

### VB-64 · Audience Profiles, per audience
`audience_variance` currently collects five audiences and then offers **one** text field to explain
all of them. Make it **selectable by the audiences they already picked** — ask per audience.

**This is the `roles` pattern exactly**, and it already works: a `RepeatableBlock` with
`seedFrom: { questionId: 'audiences_list', seedField: … }` produces one record per selected
audience. `reconcileSeededRepeatable`, `applySeededAddAnother` and `seededNameTaken` all already
handle it. **Reuse, do not invent** — and read VB-20's data-loss trap first (an added record must
land in the seed answer or reconcile deletes it).

## Home

### VB-65 · Home becomes My Files
- **Remove the top banner** — redundant with the splash.
- Top section becomes **"My Files"**, with a nav panel of **three buttons**.
- Below it, a **health panel** for the file: freshness, size, number of components — and later,
  usage/performance signals and structural diffs. **See FLAG 3.**
- Below that: links to site resources and the skills library, after the CTA for services.

### VB-66 · Rethink Download / I already have a file
Work through what these two buttons are actually for now. They were R1-10's backup story, written
before the file view, the recommendations engine and the work brain existed. Open questions: is
Download still the primary way a file leaves, or is it now a safety net? Does Import belong on Home
at all, or in the file view? Does either survive if VB-35's mapped folder ever lands?

### VB-67 · A fourth file — agents
Explore adding an **agent file** alongside Context, Skills and Actions — or another way to position
a future state where the files also instruct how to configure agents.

Cheap to hold a place for: `FlowId` already declares `'context' | 'proof' | 'skills' | 'actions' |
'drift'`, `core/files/slots.ts` is the one source of truth for what is unlocked, and V1.8 gave each
file its own answers key. A fourth locked slot costs a slot definition and a key. **Decide what it
IS before adding it**, though — "Agents.md" meaning *"how to configure your agents"* is a different
product than the other three, which are all *about the person*.

## FLAGS — read before scheduling

**FLAG 1 — DECIDED (Adam, 2026-08-24): rotation stops permanently on any interaction and never
resumes.** That satisfies WCAG 2.2.2 without a visible control, so **"Show all" can simply go**.
"Any interaction" must be read broadly and tested as such: a click anywhere in the question area, a
keypress, focus arriving, typing, opening a follow-up, pressing rephrase. Once stopped it stays
stopped for that question — it must not restart when focus leaves or when the follow-up closes.
**The same rule governs VB-60's rotating orb outline.** One implementation, both places.

The original flag, for the record — It was built as the required
pause/stop mechanism for VB-42's five-second rotation: WCAG 2.2.2 applies to content that
auto-updates, starts on its own, runs past five seconds and sits beside other content. Removing it
leaves rotating content with no way to stop it. Options: rotation stops permanently on any
interaction and never resumes; a smaller control replaces it; or the rotation itself goes. **Pick
one — plain deletion is a regression.** VB-60's rotating orb outline raises the same question.

**FLAG 2 — VB-61/62/63/64 change the ported interview data, not its presentation.**
`CLAUDE.md` is explicit: `src/core/flow/source.ts` is a verbatim port and *"any wording fix belongs
upstream in modelcitizen, then re-ported."* Changing a gate from optional to required, reordering
entity capture, and turning `audience_variance` into a seeded repeatable are all edits to that data.
Two honest paths:
- **Edit upstream and re-port** — keeps the contract, costs a round trip through the sibling repo.
- **Add a deliberate override layer** in `adapter.ts`, the way `deepDive.ts` and `addAnother.ts`
  already attach panel-era data without touching `source.ts`.
The second is probably right, and it is how three V1.x features already work. **Decide it once**,
because four items depend on it and doing it ad hoc will fragment the port's provenance.

**FLAG 3 — "usage or performance data" needs a hard line.** `docs/GUARDRAILS.md` bans analytics,
telemetry and beacons outright, with no exception. Inside VB-65's health panel:
- **Fine**: freshness, size, component counts, structural diffs — all derived from stored answers.
- **Fine**: impulse surveys the person *answers* — self-reported, local, same shape as the proof
  loop's scores.
- **Not fine**: anything measuring how the product is used and reporting it anywhere, or persisting
  a behavioural record the person did not author.
The distinction is authorship: a number the person typed is data; a number the product observed is
telemetry. Keep the panel on the first side.
