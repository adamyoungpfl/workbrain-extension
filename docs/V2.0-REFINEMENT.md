## The capture flows — real changes to how the interview collects things

### VB-60 · Choosing 1:N as orbs
The roles question (`role_names`, multi-select) stops being pills. Options become **inactive,
dimmed orbs with a glowing outline that rotates through the available choices**, indicating you can
pick one or several. **Add-new becomes a smaller, faintly glowing orb with a pulsing `+`** — an
anchor to action when nothing on screen looks clickable.

This is the brand's own object arriving in the question area, which is a good instinct. Constraints:
- The rotating outline is **auto-updating content** — same WCAG 2.2.2 question as the follow-up
  rotation, and the same answer required.
- Orbs must stay selectable by keyboard with a visible focus ring, and selection must not be carried
  by glow alone (a check, a fill, a mark).
- `PillGroup`'s existing roving-tabindex and arrow-key behaviour is a shipped accessibility
  contract — whatever replaces it must keep it.

### VB-61 · My World becomes a required, typed, repeating capture
Today `entities_gate` is a yes/no that can skip the whole block. Change to: **assume at least one**,
as a required gate for a complete file, and let the person **choose which kind of item** each one is,
since this repeats.

### VB-62 · A new item-capture cycle
For each item: **(a) type → (b) name → (c) description → (d) synonyms or shortcuts → repeat.**
Note this reorders today's flow, which asks name first (`entity_name`, `entity_type`,
`entity_relevance`, `entity_aliases`). Type-first is better for a typed repeat — it lets the later
questions phrase themselves for a person versus a tool.

### VB-63 · Initiatives: one minimum too
Same as VB-61 — at least one initiative required for a complete file. **The existing order is
right** and stays; only the gate changes, plus the add-another after each.

### VB-64 · Audience Profiles, per audience
`audience_variance` currently collects five audiences and then offers **one** text field to explain
all of them. Make it **selectable by the audiences they already picked** — ask per audience.

**This is the `roles` pattern exactly**, and it already works: a `RepeatableBlock` with
`seedFrom: { questionId: 'audiences_list', seedField: … }` produces one record per selected
audience. `reconcileSeededRepeatable`, `applySeededAddAnother` and `seededNameTaken` all already
handle it. **Reuse, do not invent** — and read VB-20's data-loss trap first (an added record must
land in the seed answer or reconcile deletes it).

## FLAGS — read before scheduling

**FLAG 1 — DECIDED (Adam, 2026-08-24): rotation stops permanently on any interaction and never
resumes.** That satisfies WCAG 2.2.2 without a visible control, so **"Show all" can simply go**.
"Any interaction" must be read broadly and tested as such: a click anywhere in the question area, a
keypress, focus arriving, typing, opening a follow-up, pressing rephrase. Once stopped it stays
stopped for that question — it must not restart when focus leaves or when the follow-up closes.
**The same rule governs VB-60's rotating orb outline.** One implementation, both places.

The original flag, for the record — It was built as the required
pause/stop mechanism for VB-42's five-second rotation: WCAG 2.2.2 applies to content that
auto-updates, starts on its own, runs past five seconds and sits beside other content. Removing it
leaves rotating content with no way to stop it. Options: rotation stops permanently on any
interaction and never resumes; a smaller control replaces it; or the rotation itself goes. **Pick
one — plain deletion is a regression.** VB-60's rotating orb outline raises the same question.

**FLAG 2 — DECIDED (Adam, 2026-08-24): use the adapter layer for all of it.**
`src/core/flow/source.ts` stays a **verbatim port and is never edited**. The gate changes, the
type-first entity cycle and the per-audience repeatable are all attached in `adapter.ts`, exactly
the way `deepDive.ts` and `addAnother.ts` already attach panel-era data.

**Do it as one override module, not four ad-hoc edits** — otherwise the port's provenance fragments
and nobody can tell later which questions came from modelcitizen and which this repo invented. One
file, one place to read, each override carrying why it exists. `adapter.test.ts` should assert that
`source.ts`'s own exports are untouched by any of it.

The original flag, for the record —
`CLAUDE.md` is explicit: `src/core/flow/source.ts` is a verbatim port and *"any wording fix belongs
upstream in modelcitizen, then re-ported."* Changing a gate from optional to required, reordering
entity capture, and turning `audience_variance` into a seeded repeatable are all edits to that data.
Two honest paths:
- **Edit upstream and re-port** — keeps the contract, costs a round trip through the sibling repo.
- **Add a deliberate override layer** in `adapter.ts`, the way `deepDive.ts` and `addAnother.ts`
  already attach panel-era data without touching `source.ts`.
The second is probably right, and it is how three V1.x features already work. **Decide it once**,
because four items depend on it and doing it ad hoc will fragment the port's provenance.

**FLAG 3 — "usage or performance data" needs a hard line.** `docs/GUARDRAILS.md` bans analytics,
telemetry and beacons outright, with no exception. Inside VB-65's health panel:
- **Fine**: freshness, size, component counts, structural diffs — all derived from stored answers.
- **Fine**: impulse surveys the person *answers* — self-reported, local, same shape as the proof
  loop's scores.
- **Not fine**: anything measuring how the product is used and reporting it anywhere, or persisting
  a behavioural record the person did not author.
The distinction is authorship: a number the person typed is data; a number the product observed is
telemetry. Keep the panel on the first side.


## DECIDED — the help content carries process, not just definitions
Adam, 2026-08-24. The follow-up/help system is **more than additional information**: it also
carries **how-to and process material**, and VB-68's refresh instructions live in it so someone can
find out how to do it in context.

**This resolves the outstanding help-panel scope question.** The area is not a glossary. Its job is
"what you need to know to act here," which covers both *what does this question mean* and *how do I
do the thing this screen is asking of me*.

**One distinction the implementation has to respect.** The two kinds of content belong in different
places, even though they share a mechanism:
- **Definitional** follow-ups attach to a *question* (`Step.deepDive`, already shipped, 26 of them).
- **Process** material attaches to a *task* — and VB-68's refresh is not an interview question at
  all. It happens after a file exists, when someone is using it with their AI. Its natural home is
  the file view or the download flow, not a rotating link under question thirty-one.

So: one content system, two attachment points. Do not force process copy onto a `Step` just because
that is where `deepDive` already hangs — add a second attachment for surfaces, and say in
`deepDive.ts`'s header which kind lives where. VB-43's illustration style is the same conversation
and should be scoped against both kinds, not just the definitional ones.

**Knock-on for VB-42**: the rotating follow-up links will now cycle a mix of "what does this mean"
and "how do I do this" where both exist on one screen. Confirm that reads sensibly rather than as
two unrelated voices taking turns.

## VB-68 · The usage log — the file records what got used
Adam's idea, 2026-08-24. Instead of the product observing anything, **the file carries an
instruction asking the AI to record what it used**, and the panel reads that back when the file
returns. Cross-service, because each line names who wrote it.

### The design correction that makes it work
**Do not ask the AI to increment a number.** It has no memory across conversations and no record of
past use, so asked "how many times have you used this," it produces a plausible integer rather than
a true one — a dashboard built on confabulation, which is worse than none because it looks real.

**Ask it to append one line for this session. The app counts the lines.**

```markdown
## Usage log
<!-- AI: append one line below when you use this file. Never edit or remove existing lines. -->
2026-08-24 | claude | 2. About Me, 6. How I Communicate
2026-08-25 | chatgpt | 4. Initiatives
```

Every number is then countable from lines that exist. The distribution across services falls out
for free. And **"which sections actually get used"** — the genuinely valuable signal, and one no
amount of local observation could ever have produced — becomes answerable.

### Disclosure — the reasoning, to be confirmed before shipping
The panel **observes nothing**. It parses a file the person hands it, which is exactly what
`core/files/parse.ts` already does with their answers. Whether that file contains answers or a
usage log, the act is identical and the person controls both what is in it and whether to import it.
On that reading no new data category is ticked and `store/PRIVACY.md` needs no new sentence.

**The wrinkle to resolve, not assume:** this is the first content in the file the person did **not
author** — a third party wrote it, about their behaviour. That is still their file and their choice
to import, but it deserves a sentence in the privacy policy saying so plainly rather than relying
on the existing "everything you type" clause, which would no longer cover everything. Draft that
sentence and check it before the feature ships.

### Sustainability — the part that will bite if ignored
- **The log grows without bound.** Decide the cap now: keep the last N lines, or the last N months,
  and have the panel say what it dropped. A file that is 60% log is a file people stop using.
- **`parse.ts` must read it without treating it as answers**, and must not fail on a malformed or
  hand-edited log — `docs/GUARDRAILS.md`'s degradation rule applies: an unreadable log is skipped,
  never a reason to reject the file.
- **The format needs a version marker.** This is the first thing in the file whose shape may change
  after people have real ones.
- **It only accrues if someone deliberately refreshes.** That is a ritual, not a background
  process — which matches everything else here, but it means **the instruction and the process are
  the feature**, not the parser. If nobody refreshes, the log is empty and the panel says so
  honestly rather than showing zeros as if they were measurements.

### What ships
The instruction block in the generated file (alongside the System Grounding Rule, in
`core/files/source.ts`'s verbatim-content register), the parser, the count-from-lines derivation in
`core/`, and the display. Plus the copy that tells someone how and when to refresh.

**Accept**: the block is written into every generated file; a file with no log parses exactly as
today; a malformed log is skipped without failing the import; counts come from counting lines, never
from a number the AI wrote; the cap is enforced and disclosed; the panel distinguishes "never
refreshed" from "used zero times"; round-trip tests still pass.

## VB-69 · The stage stops having its own background
The globe's stage paints `--globe-field` while the drawer around it paints its own field, so a
lighter rectangle sits inside a darker one. **They become one colour.**

This finishes VB-50's job rather than reversing it. VB-50 made the drawer one surface edge to edge
and deliberately removed List's separate pane — the globe's stage is the same class of thing and
was missed. `BrainGlobe.css` sets `background: var(--globe-field)` in two places; both go, and the
drawer's field shows through.

**Check while removing it**: the orbs' and edges' contrast was measured against `--globe-field`
(VB-54's lighting, VB-45's 3:1 hairline). If the drawer's field differs at all, re-measure by
decoding painted pixels rather than assuming the tokens are close enough.

## VB-70 · The visual's height governs the mode, both ways
The stage's displayed height becomes the **minimum for Brain to be available**:
- Drag **below** it → auto-transitions to List.
- Drag **above** it while List is open → Brain becomes offerable again.

**Half of this already ships and should be reused, not rebuilt.** `src/core/drawer/mode.ts` already
has `BRAIN_STAGE_IDEAL = 208`, `BRAIN_MIN_HEIGHT` and `BRAIN_OPEN_HEIGHT`, and V1.6's VB-30 already
hands Brain over to List below its threshold. What is genuinely new is **the return leg** — Brain
coming back when there is room again — and pinning the threshold to the stage's real displayed
height rather than a separate constant.

Two things to get right: the switch must not **thrash** at the boundary (a drag hovering on the
threshold cannot flip modes every frame — hysteresis, or commit on drag end), and a person who
explicitly chose List must not be **yanked into Brain** just because they made the drawer taller.
Auto-transition *out* of Brain is a necessity; auto-transition *into* it is a suggestion. Prefer
"Brain becomes available again" over "Brain reopens".

The freed vertical space is also where the back control can sit more comfortably (VB-59's disc).

## VB-71 · Show that the brain can be turned
Nothing on screen says the globe is draggable. Add a **one-time cue** — an icon, a brief hint, or a
single nudge of the geometry — that says it can be moved with the cursor.

Constraints: it appears **once**, not every visit (persist a seen flag in `wb:prefs`, which is
already the home for this kind of thing); it must not block the first drag; and under
`prefers-reduced-motion` it is a static affordance rather than a demonstration. Keyboard users
already reach the nodes by tab, so this is specifically about the pointer gesture.
